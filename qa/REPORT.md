# Отчёт о проверке Roomly

**Дата и стенд** — 24 ноября 2026 года, [опубликованная форма Roomly](https://rcsi-science.github.io/demo-roomly/). **Требования** — [README задания](../README.md#ожидаемое-поведение).

Подтверждены пять дефектов. Форма принимает бронь с совпадающими началом и окончанием, длительностью вне допустимых границ, прошедшим временем сегодня, некорректной почтой и дробным количеством участников. Автотесты на опубликованном стенде завершились с результатом `3 passed, 1 xfailed`.

**Окружение.** Windows 26H2 x64, сборка `26300.10075`. Ручные сценарии выполнены через интерфейс формы во встроенном браузере Codex. Дефекты повторно подтверждены, скриншоты сделаны и автотесты запущены в Chromium `156.0.8078.4` (headless), Python `3.14.4`, Playwright `1.64.1`, pytest `8.3.5`, pytest-playwright `0.7.1`. Для повторной проверки использована зона `Europe/Moscow`.

**Время** — около 15 минут на проверку, автотесты и оформление отчёта. В оценку входят ручные сценарии, повторное воспроизведение и проверка запуска.

## Дефекты

**Общие предусловия.** Открыть стенд. Выбрать «Малая», дату завтра, начало `10:00`, окончание `10:30`, 4 участника, имя «Тестовый заявитель» и почту `qa@example.com`. Для каждого дефекта начать с этих данных. На скриншотах дата «завтра» — 25 ноября 2026 года.

### BUG-01 — Форма подтверждает бронь с нулевой длительностью

- **Шаги.** Изменить окончание на `10:00`. Нажать «Забронировать».
- **Ожидается.** Заявка отклоняется, поле «Окончание» сообщает об ошибке. Окончание должно быть позже начала.
- **Факт.** Появляется «Бронирование создано.» для интервала `10:00–10:00`.
- **Приоритет P1.** Пользователь получает подтверждение встречи без интервала. Совпадающие значения можно выбрать из обычных элементов формы.
- [Скриншот](evidence/BUG-01.png) · [Автотест](../tests/test_booking.py)

### BUG-02 — Форма принимает длительность вне диапазона

- **Шаги.** При начале `10:00` указать окончание `10:29` и отправить форму. Повторить с окончанием `14:01`.
- **Ожидается.** Обе заявки отклоняются. Минимум — 30 минут, максимум — 4 часа.
- **Факт.** Форма подтверждает оба интервала. Контрольные значения `10:30` и `14:00` тоже принимаются.
- **Приоритет P1.** Форма пропускает интервалы за обеими границами основного правила бронирования.
- [Скриншот для 29 минут](evidence/BUG-02-short.png) · [Скриншот для 241 минуты](evidence/BUG-02-long.png)

### BUG-03 — Форма подтверждает бронь на прошедшее время сегодня

- **Условие.** Текущее локальное время позже `00:30`.
- **Шаги.** Выбрать сегодняшнюю дату, указать `00:00–00:30` и нажать «Забронировать».
- **Ожидается.** Заявка отклоняется с ошибкой времени.
- **Факт.** Форма подтверждает бронь на сегодня с `00:00` до `00:30`.
- **Приоритет P1.** Пользователь получает подтверждение встречи, которая уже должна была закончиться.
- [Скриншот](evidence/BUG-03.png)

### BUG-04 — Форма принимает почту с двумя @

- **Шаги.** Ввести `qa@@example.com` в поле «Рабочая почта». Нажать «Забронировать».
- **Ожидается.** Ошибка формата почты, заявка отклоняется.
- **Факт.** Форма подтверждает заявку без ошибки почты.
- **Приоритет P2.** Пропускается очевидная опечатка в обязательном контакте. Влияние в демо ограничивается ложным подтверждением корректности заявки, поскольку приложение не отправляет почту.
- [Скриншот](evidence/BUG-04.png)

### BUG-05 — Форма принимает дробное количество участников

- **Шаги.** Ввести `1.5` в поле «Участники» и нажать «Забронировать». Локализованное поле может показать `1,5`.
- **Ожидается.** Ошибка количества участников, заявка отклоняется. Количество людей должно быть целым.
- **Факт.** Форма подтверждает заявку без ошибки участников.
- **Приоритет P2.** Форма допускает некорректное значение численности. Проверенные целочисленные границы комнат работают.
- [Скриншот](evidence/BUG-05.png)

## Вопросы, допущения и ограничения

- Границы длительности считаются включительными. Начало и окончание относятся к выбранной дате. Допустимы ли встречи через полночь? Есть ли рабочие часы и предел даты бронирования?
- Для сегодняшней даты ориентиром служит локальное время браузера. Нужна ли фиксированная зона офиса? Допустимо ли начало в текущую минуту? Что происходит с формой, открытой до полуночи?
- Для почты проверен синтаксис. Требуются ли корпоративные домены и поддержка интернационализированных адресов? Для числа участников принято, что оно целое.
- Покрытие включает валидацию, вместимость, подтверждение, сброс и сетевое поведение одного корректного сценария. Проверка фактической доступности комнат, конфликтов бронирования и доставки уведомлений потребует серверной части.
- Нативные поля даты, времени и числа зависят от браузера и локали. Проверка ограничена десктопным Chromium. Мобильные устройства, специальные возможности, другие часовые пояса и переход через полночь не проверялись.

## Автотесты и запуск

Команды запуска из корня приведены в [README](../README.md#запуск-автотестов). Последний прогон выполнен командой `python -m pytest --base-url https://rcsi-science.github.io/demo-roomly/`. Явный адрес позволяет переопределить `BASE_URL` окружения.

| Сценарий | Итог |
| --- | --- |
| Smoke из исходного каркаса | PASS |
| Корректная бронь на нижней границе длительности | PASS |
| Превышение вместимости малой комнаты, 5 при лимите 4 | PASS |
| Отклонение совпадающих начала и окончания, BUG-01 | XFAIL |

Регрессионный тест ожидает отклонение заявки. После исправления строгий `xfail` даст `XPASS(strict)` и потребует убрать метку. Сбой навигации и неожиданный статус формы приводят к обычной ошибке прогона.

После запуска Docker Desktop сессия получила `Access is denied` при подключении к каналу `dockerDesktopLinuxEngine`. Команда с Docker Compose `v2.35.1-desktop.1` не дошла до запуска контейнера. Результат выше получен прямым запуском Python.
